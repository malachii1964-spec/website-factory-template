# MALACHII North-Star Architecture

## Positioning

MALACHII is not another agent runtime. Existing runtimes, models, remote agents and tool protocols are resources **beneath** MALACHII governance.

## Architectural hierarchy

1. **Sovereign Constitutional Layer** — host precedence, Super-User authority within MALACHII, non-bypassable truth/quality/authorization rules.
2. **Distributed Control Plane** — objective, identity, policy, capability, registry, routing, scheduling, evidence, quality, release, reconciliation and ledger control.
3. **Adaptive Cognitive Mesh** — models, agents, councils, skills, context, memory, knowledge and evidence workers dynamically composed for objectives.
4. **Autonomous Execution Plane(s)** — browser, shell, sandbox, filesystem, code, APIs, build, deployment and other raw work.
5. **Interoperability Fabric** — A2A for remote agents, MCP for tools/data, ordinary APIs/events as appropriate.
6. **Experience Plane** — Command Center and user-facing objective/trace/artifact experience.

## Core laws

- Control decides and reconciles; execution performs.
- Desired state never overrides observed reality.
- Capability != authorization.
- Claimed capability != observed/attested capability.
- Adaptive below; constitutional above.
- Smallest sufficient intelligence topology; agent count is not a quality metric.
- Independent verification must use genuinely distinct governed resources where required.
- Successful build != release-qualified result.
- Protocol interoperability never grants policy authority.
- Memory/evidence retain provenance and cannot silently become constitutional truth.
