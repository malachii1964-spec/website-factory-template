# MALACHII Target — Distributed Multi-Agent Control Plane + Adaptive Cognitive Mesh

`DMACP` and `Cognitive Mesh` are MALACHII architectural terms in this project, not represented here as formal external standards.

## Target topology

```text
Super-User / Host Authority
        |
Sovereign Constitutional Layer
        |
Distributed Multi-Agent Control Plane
  Objective | Policy | Identity | Registry | Router
  Scheduler | Evidence | Quality | Release | Ledger
        |
Adaptive Cognitive Mesh
  Models | Agents | Councils | Skills | Memory | Evidence
        |
Autonomous Execution Planes
  Browser | Shell | Sandbox | Files | APIs | Build | Deploy
        |
Interoperability
  A2A sideways | MCP downward | ordinary APIs/events where appropriate
```

## Architectural rules

1. **Adaptive below, constitutional above.** Work topology may reorganize itself; authority roots cannot.
2. **Capability != authorization.** A worker cannot grant itself permission because it learned how to perform an action.
3. **Elastic topology, not agent-count theater.** Use the minimum sufficient workers for quality, diversity, latency and assurance.
4. **Independent-first verification.** Independence must be real enough to avoid the same worker masquerading as two reviewers.
5. **Structured epistemic exchange.** Agents exchange claims/evidence/tests/uncertainty, not uncontrolled hidden-reasoning dumps.
6. **Observed state wins.** Desired completion is reconciled against execution/evidence/quality reality.
7. **Agent Foundry is quarantined by design.** Synthesized specialists must be sandboxed, evaluated, attested, minimally authorized and revocable before joining the mesh.
8. **Protocols are transports, not governance.** A2A/MCP do not replace MALACHII policy, trust or release control.
